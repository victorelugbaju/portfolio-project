Design System The System — v1 Swiss editorial · type-led · dark

The parts, and how they behave.

The full language the portfolio is built from — every token, element and component, plus the principles that govern them. Each interactive state is drawn as its own static object (Default beside Hover, Focus, Selected), because a design-tool import reads one frozen frame and never a :hover. Everything holds to the same contract as the site — flex and gap for rhythm, borders as strokes, no CSS-drawn shapes — so it lands clean in Figma, where you take it from here.

03 — Spacing & layout

12 columns · one radius

Rhythm is carried by flex gap and padding, never margin — so it maps one-to-one onto Figma auto-layout. One radius across the whole system: 2px. The page is a 12-column field capped at --maxw, gutters at --gutter, side margins fluid at --margin.

--cols 12 Grid columns.
Radius 2px Every corner — frames, chips, buttons.
Short pages — .page--short

Added 2026-10-05 for 404.html. A page whose content does not fill the viewport otherwise drops its footer wherever the content stops, leaving a band of dead paper underneath that reads as a broken page rather than a short one. Put .page--short on <body> alongside .page and the footer sits on the fold.

It is flex column plus flex: 1 0 auto on main — not a fixed footer, which would overlay content on a page that later grows and would not survive the Figma import as a layout. Harmless on long pages: main simply grows past the minimum. Currently used by 404.html only.

Lightbox — .lightbox

Added 2026-10-05. Tap or click any .card__img inside a .card__frame to open it full-screen; Esc or the Close button dismisses it. Not drawn live here — this page ships no JS, and the overlay is built by main.js on first use rather than written into every page, so there is nothing static to show.

Why it exists. The case-study boards are persona sheets and UI screenshots — they carry type. At a 390px viewport they are downscaled 7× to 14× (sprout-persona.png is 4800px wide shown at 348px), so 40px type in the board lands near 3px. The evidence in a case study was decoration on the device most people read it on. Note srcset would not have fixed this: it cuts bytes, not downscale.

Sizing rule. The image opens at roughly 3× the fitted size, capped at its own pixel width, with the scroll centred. Both obvious alternatives were built and measured first, and both were wrong: fitting to the viewport gave 359px on a phone against 348px inline — an "enlarged" view smaller than the page — while natural size gave a 10× crop you could not navigate.

Rules it must keep. Images inside a link are left alone, so work cards still navigate. An image that has not loaded does not open, so the red placeholder state never produces an empty overlay. Every enlargeable image gets role="button", tabindex="0" and a descriptive label, so the keyboard reaches what the cursor does. The scroll lock it shares with the mobile menu is reference-counted — see the note in main.js for why that matters.

04 — Elevation & surfaces

Two planes, no shadows

Depth is a surface change, not a shadow. The page is --paper; anything that lifts — a frame, a stage, an elevated panel — goes to --paper-warm, which is lighter than the ground in dark mode. A 1px --rule-soft stroke does the containing. No drop shadows anywhere; they don't belong to this material.

05 — Motion

Surgical, not decorative

One easing curve, three durations. Micro-feedback (hover tints, arrow nudges) runs at --fast; component transitions at --base; entrances and the type reveal at --slow. Nothing bounces, and everything collapses under prefers-reduced-motion.

--ease cubic-bezier(.2, 0, 0, 1) The only curve. Fast out, soft in.
--fast 120ms Hover colour, border, arrow nudge.
--base 280ms Focus line, image scale, transforms.
--slow 640ms Scroll reveals, line reveal.

07 — Responsive

Where the layout turns

Breakpoints are placed where a specific composition stops working, not on a device grid. The 901px line is also the pointer-only threshold: cursor effects (portrait parallax, the View badge) run above it and are simply absent below.

≥ 901px pointer effects on Parallax + cursor badge live here only.
≤ 1120px principles → 2-up Four-column blocks fold to pairs.
≤ 900px rails unstick Sticky side-rails become headers.
≤ 860px spreads stack Feature rows go media-over-panel.
≤ 768px nav → burger Links become the index sheet. The bar centres, drops to 60px and takes a ground once scrolled.
≤ 640px --t-meta → 10px Grid unstacks to one column.
≤ 360px section heads wrap Title and its mono label stop sharing a row.

--t-meta drops to 10px below 640px and has to stay there. It is load-bearing, not taste: at 11px the case-study section heads no longer fit a 320px screen and the page silently zooms out. Measured, not assumed.

Below 360px, .section__head wraps. Two white-space: nowrap items in one space-between row have a combined minimum width, and on a case-study page the title plus "03 — Problem & solution" exceeds 320px of it. A browser does not clip that — it widens the layout viewport to fit, zooming the whole page out and dragging every fixed element (the bar, the read-progress rule) past the screen edge. The symptom looks like a bug in .progress; the cause is a row that wouldn't wrap.

07b — Touch

The 44px floor

A target sized for a cursor is not a target. A pointer is one pixel and lands where it is aimed; a fingertip is about 9mm, arrives at an angle, and covers the thing it is reaching for. 44px is the floor, and below 768px every control clears it.

The rule is grow the target, never the type. Padding and min-height do the work, so composition and type scale are untouched — the page looks identical, it just stops fighting a thumb. These are easy to miss by eye, because every one of them looks right at any size; the list below was found by measuring rendered boxes on real pages at 390px.

.field__input 35 → 45px Padding added above the text, so the drawn underline does not move. Font stays 16px — below that iOS zooms the page on focus.
.channel__value 21 → 44px The four ways to actually reach him — the highest-consequence miss on the page.
.nav__mark 12 → 44px The home link on all eight pages, and the smallest target on the site.
.section__action 13 → 44px The only route from the homepage grid into the work index.
.btn / .cta__link 40, 21 → 44px Near enough to look right, far enough to miss.
tap highlight signal @ 18% The system grey-blue flash retinted to the palette. Not set to transparent — the flash is the only confirmation a thumb gets, since a phone has no hover.
scroll-padding-top 92 / 76px Anchor jumps clear the fixed bar. Without it a jump to #work parks the heading under the bar and reads as a dead link.

⚠ These live at the very end of css/style.css and must stay there. A media query adds no specificity, so they only win by coming after the components they override — placed higher, .field__input's own padding shorthand silently reset them and the field stayed 35px while looking fixed.

26 — Prototype embed

Poster first, iframe on request

A live Figma prototype behind a click-to-load poster. The launch control is a real <a> to the prototype URL — JS upgrades it into an inline <iframe> on desktop and otherwise leaves it alone, so the prototype is reachable with JS off, on a phone, and if the embed fails. The embed URL lives in data-proto-embed; the href is the plain share link. Keep the two in sync.

Never loaded eagerly: the embed drags in Figma's own runtime and most visitors never press play. Below 901px the upgrade is skipped entirely — a desktop prototype in a phone viewport is a pinch-zoom puzzle, and the Figma app handles it better than an iframe can. 27 — Shots row

Three across, or four as 2×2

A short set of captioned stills showing finished screens. Reuses .card__frame and .card__placeholder wholesale, so the "image needed" spec card and the is-empty fallback already apply. Wraps to one per row below 640px.

Three across is the default and the cap for a single row — past that a reader stops looking. For four screens use .shots--pair, which holds two per row: four across gives each frame a quarter of the width and the UI inside stops being legible. The pair basis is calc(50% - (var(--gutter) / 2)), not a flat 50% — at exactly half, two items plus the gap between them overflow the row and the second wraps, leaving a single column of four. The subtraction is what makes two-up hold.

28 — Stacked scroll

Homepage project deck

The homepage index is a deck, not a grid. Each project is a full-width panel pinned with position: sticky at a slightly lower offset than the one before it, so scrolling slides each new project up over the last and leaves a stack of edges under the nav. Sides alternate — .stack__card--flip reverses the row, exactly like .project--flip on the work index, and it alternates with the slot, never travels with the project.

Three things break this silently, all of them measured rather than assumed. Any ancestor taking overflow or a transform becomes the containing block and the pinning dies. Each panel needs an opaque fill, or the covered panel shows through and the effect reads as a rendering fault. And the last panel needs runway to hold before the deck releases — that runway must be a sibling box (.stack__runway), because margin-bottom on the last card moves the release point by exactly what it adds to that card's own margin box, collapsing its pin window to nothing, and padding on .stack sits outside the content box the constraint tracks. Both alternatives were tried and both fail.

The media and panel tracks also reset to flex: none there: once the row becomes a column, a row-axis flex basis resolves against height.

30 — Read progress

Case studies only

A 2px hairline pinned to the top of the viewport, above the nav, reporting how far into a case study you are. It exists because a case page is the one place on this site with an unknown length — every other page is scannable in a screenful or two, and a progress bar on them would be reporting a fact nobody asked about.

Same contract as the experience rail: scaleX on a real element, never width, because this writes on every scroll frame and width relayouts. No transition — easing a bar that reports position makes it lag the scroll it describes, which reads as a stutter rather than as smoothing. It runs under reduced motion for the same reason the xp rail does: this is a scrollbar, not a flourish. Two flat nested elements, so it imports as a frame inside a frame.

At 38% — .progress__fill

Scrollable distance can be zero — a short page, a phone in landscape — and dividing by it puts NaN into a transform, which blanks the bar rather than erroring. The JS guards for it. It also redraws on load, because lazy images land after the first measurement and change scrollHeight underneath it.

31 — Full-bleed plate

One per section, at most

One image running edge to edge, carrying a case-study section on its own. This is the only device allowed to break the text column, which is exactly why there is at most one per section — a page where everything breaks the column has no column left to break.

The bleed is achieved by sitting outside .section — a direct child of <main> with no inline padding. Never with a negative margin: the import contract bans margin for rhythm, and a negative one lands in Figma as an overlapping frame. The caption is optional and usually omitted — a hero plate carries no caption at all. When present it keeps the page margin and the same 1560px centring .section uses, so it lines up with the body copy above and below while the image runs past it. Ratio is 16:9, wider than the 3:2 the grid cards take, because a set-piece earns a cinematic ratio and a thumbnail does not — dropping to 4:3 below 720px, where 16:9 becomes a ~200px letterbox slot with unreadable screens inside it.

33 — Counted facts

Counted, not claimed

How a case study closes when the work never shipped. Every figure describes the artifact — taps, states, screens, buttons removed — and never an effect on a user, because a concept with no instrumentation has no baseline to claim one from. "40% faster checkout" on an unshipped app is the fastest way to make a reviewer distrust the honest parts of the same page.

.landed__source is load-bearing, not decoration. Each figure carries the method that produced it, which makes the component self-policing: a number you invented has no source line to write. If the source can't be filled in, the figure is deleted rather than guessed. Figures are mono, not the display serif — they read as measurements, and the serif would give them the register of a headline, which is authority this work hasn't earned yet.

34 — Case figure

One exported board

For content that is itself a designed artifact — a persona board, a flow map, a style tile. Rebuilding those in markup means maintaining the same content in two places and letting them drift, so they arrive as a single export instead.

Image needed 16:9 — 2400×1350 minimum.

Deliberately nothing but an aspect ratio on .card__frame — the spec card, the is-empty fallback, the border and the fill are already there, and a component that needs one property should declare one. Not to be confused with .plate, which breaks the column and runs edge to edge; this sits inside the section on the same measure as the copy around it. Drops to 4:3 below 720px, where 16:9 becomes a ~200px letterbox and a board's type stops being readable.

Match the frame to the export, not the export to the frame. .card__img is object-fit: cover, so a 3:2 board dropped into the 16:9 default silently loses ~18% of its height — survivable on a photograph, fatal on a persona board whose content is text. Check the asset's real ratio and add .case-figure--3-2 where it fits; a new modifier here is cheaper than re-exporting a board, and both ratios are in use across the case studies today.

35 — Process row

Four steps, one line

A design process read as a single ruled diagram rather than as four cards: one hairline across the top, vertical hairlines between the steps, an oversized display numeral opening each. Nothing is boxed — the rules do the work, the same move the facts rail and the point lists make.

01

Research

What you actually did, not what the step is called.

02

Structure

Information architecture, flows, what the product had to know.

03

Interface

Component system, visual language, the screens themselves.

04

Validate

What you tested, what broke, what changed because of it.

flex: 1 1 0 with min-width: 0 is what holds four equal columns on one line. A percentage basis leaves the gutters unaccounted for and wraps the fourth step; a zero basis makes the four share the leftover space exactly, and min-width: 0 stops a long word setting a floor wider than its quarter and forcing a wrap anyway. Separation is by border rather than gap — a gap between bordered columns reads as four detached slabs, and the point is one continuous rule the steps hang off.

Numerals sit at --ink-30 so they read as structure rather than as content competing with the titles; signal on hover is the row's one moment of colour. Four columns stop being readable long before they stop fitting, so it goes 2×2 at 900px and single-column at 560px — and each break rebuilds the rules, because a left border on a wrapped row draws in the middle of nowhere.

Principles

36 — The Figma contract

Five rules, non-negotiable

Every rule in this system exists so the markup survives an import into Figma as clean auto-layout. Break one and components arrive as absolutely-positioned junk, or vanish entirely. When you extend the system in code, keep to these.

01

Flex + gap for all rhythm

Never margin. Flex with gap and padding maps one-to-one onto auto-layout; margins don't survive the trip.

02

No visible ::before / ::after

Pseudo-elements aren't in the DOM, so they vanish on import. Anything visible — dots, rules, marks — is a real element.

03

No clip-path, no CSS shapes

Drawn shapes flatten. A shape is SVG or it's nothing. The one exception, the duotone, is a real SVG filter.

04

Google Fonts only

They're native in Figma, so type doesn't substitute to Roboto on the way in. Instrument Serif, Inter Tight, Geist Mono.

05 — Borders are fine. They import as strokes, so frames and pills can carry them freely.

37 — Voice

Loud where it's unfinished

The system has a content posture, not just a visual one. Placeholders announce themselves — a missing image names its exact file, an unanswered outcome turns signal-italic, a held slot says Reserved. Nothing unfinished is allowed to look finished. Copy stays plain and honest: a concept is called a concept, and no metric is claimed that wasn't measured.
